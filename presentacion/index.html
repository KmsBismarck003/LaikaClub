Bloque 02 · Tecnología con propósito

Cada tecnología responde a una necesidad real del negocio

React 19 · Vite · SolidJS · React Native Expo

Cobertura en cualquier pantalla

Por qué: Dominio previo del equipo y portabilidad total de escritorio a móvil Android e iOS.
Ventaja: Compilación rápida en Vite, biometría nativa y exportación PDF en SolidJS.
Compromiso: Requiere disciplina de versiones entre seis aplicaciones independientes.

Java 17 · Spring Boot 3.2.5 · JPA · Security

Por qué Java y no Python en ventas

Por qué: Tipado estático estricto y concurrencia real sin bloqueo global en compras simultáneas.
Ventaja: Hilos virtuales, bloqueo con ReentrantLock y respuesta HTTP 409 anti-sobreventa.
Compromiso: Mayor memoria base JVM, optimizada a 150 MB con SerialGC por servicio.

Python · FastAPI · HTTPX · PySpark 3.5

Gateway veloz y motor analítico

Por qué: Enrutamiento asíncrono ligero en Pilgrim y ecosistema nativo para Machine Learning.
Ventaja: Caché GET de 60 s, clustering K-Means, PCA y detección de bots en tiempo real.
Compromiso: Estandarizar contratos JSON entre backends Java y Python.

MySQL 8.0 · MongoDB · Docker · Terraform

Persistencia íntegra y nube reproducible

Por qué: Transacciones ACID en MySQL para ventas más flexibilidad documental en MongoDB.
Ventaja: Esquemas segregados por microservicio y despliegue automatizado como código.
Compromiso: Gestión ordenada de migraciones y políticas de respaldo diferenciadas.

Bloque 03 · Retos superados

Cuatro obstáculos reales convertidos en ventaja técnica

1. Desacoplamiento por roles y móvil
ProblemaRutas y acciones desconectadas entre SPAs, app móvil y microservicios.
Alternativa descartadaConectar cada cliente directo a 9 puertos internos.
Solución y resultadoPilgrim FastAPI unificó rutas por rol y contratos HTTP en un solo punto.
2. Versiones y regresiones modulares
ProblemaIncompatibilidad de versiones y cambios que rompían funciones ya activas.
Alternativa descartadaInstalación manual en host compartido sin pruebas previas.
Solución y resultadoAislamiento en Docker Compose y compuertas CI con 60 pruebas automáticas.
3. Bases de datos y rutas en nube
ProblemaDesconexiones en MySQL, datos inconsistentes y saltos a puertos locales.
Alternativa descartadaEsquema único acoplado con direcciones fijas en código.
Solución y resultadoRed privada Docker, esquemas separados, consultas agregadas y variables por entorno.
4. Regiones, capacidad y costos Azure
ProblemaRegiones restringidas, poca RAM para 9 servicios y presupuesto limitado.
Alternativa descartadaMúltiples servidores dedicados fuera de presupuesto.
Solución y resultadoTerraform en VM ARM64 con swap 8 GB, JVM a 150 MB y portabilidad entre suscripciones 24/7.

Bloque 03 · Servicios, redes y operación en la nube

Detalles de infraestructura, seguridad, monitoreo y FinOps

Redes y seguridad perimetral

Aislamiento de punta a punta

  • Topología Terraform: Resource Group rg-laikaclub, VNet 10.0.0.0/16, Subred 10.0.1.0/24 e IP estática.
  • Firewall NSG: Solo abre puertos 80, 443 y 22 con llave SSH RSA 4096.
  • Cifrado y blindaje: TLS con Certbot, SSL Pinning en LaikaMobil y red interna Docker oculta.

Cómputo y despliegue

VM ARM64 y 11 contenedores

  • Servidor base: Ubuntu 22.04 ARM64 Standard_B2ps_v2, 2 vCPU, 8 GB RAM, SSD 32 GB y Swap 8 GB vía cloud-init.
  • Despliegue continuo: GitHub Actions ejecuta deploy_remote.sh actualizando Pilgrim, Nginx y Docker.
  • Reto de memoria resuelto: JVM afinada con SerialGC, Xmx150m e hilos virtuales.

Monitoreo, disponibilidad y costos

Operación 24/7 eficiente

  • Monitoreo activo: Endpoint /api/health en Pilgrim más bitácoras duales de latencias y errores HTTP.
  • Continuidad: Política restart: always en contenedores, compresión Gzip y portabilidad rápida con Terraform.
  • Control FinOps: Costo cercano a 30 USD al mes con alertas automáticas al 80% y 95%.
Convivencia híbrida: Frontends ligeros en Vercel CDN, app móvil en Expo y Play Store, y núcleo transaccional protegido en Microsoft Azure. Terraform + Docker
